# S3-compatible adapter

`backend/src/providers/s3/**` — the `VIA_S3` `s3` adapter from `provider-contract.md` §11.

| File | Role |
|---|---|
| `index.ts` | `S3Provider implements StorageProvider`, `s3Provider`, `createS3Provider()`, `registerS3Provider()`, upload/download/list/meta/folder/share/health logic, `guardedBody`, `StreamCursor` |
| `client.ts` | `resolveSettings()`, `buildClient()`, `sendCommand()` (SSRF gate, retry, `mapS3Error`, `ctx.signal`), constants (`DEFAULT_PREFIX`, multipart defaults, `MAX_MULTIPART_PARTS`, `MAX_QUOTA_PAGES`) |
| `presets.ts` | `S3_PRESET_IDS`, `getPreset()`, `resolveS3Target()` — catalog `s3Preset` merge with user-override precedence |
| `keys.ts` | `prefix/userId/fileId/fileName` layout, folder markers, name sanitisation, `assertOwnKey` tenant isolation |
| `mime.ts` | `FOLDER_MIME_TYPE` (`inode/directory`), extension → MIME table |
| `errors.ts` | `mapS3Error()` → security-contract/provider-contract §5 taxonomy |
| `presign.ts` | `createPresignedGetUrl()`, `objectTarget()`, `resolveShareExpiresIn()` — standalone SigV4 presigner (no `@aws-sdk/s3-request-presigner`) |

The adapter is exported through `providers/index.ts` by the coordinator; this agent owns
only the directory above, its tests (`backend/src/__tests__/providers/s3/**`) and this
document.

## Auth setup (access keys)

S3 accounts never use OAuth. The user creates an **access key pair** in their storage
provider (AWS IAM user/role keys, or the provider's S3-compatible key) and connects the
account with `POST /connected-accounts/s3`:

```jsonc
{
  "name": "My bucket",
  "bucket": "my-bucket",
  "region": "eu-central-1",
  "endpoint": "https://s3.eu-central-1.amazonaws.com", // optional, '' or omitted = AWS default
  "accessKeyId": "AKIA...",
  "secretAccessKey": "...",
  "forcePathStyle": false,   // optional
  "quotaBytes": "5368709120" // optional, string digits
}
```

The route validates the body with zod, runs the SSRF gate on the endpoint
(`ERR_SSRF_BLOCKED` → HTTP 400 `SSRF_BLOCKED`), upserts `S3StorageConfig` (keys stored
encrypted), runs `testS3Connection` and `syncS3Quota` before returning.

Minimal IAM policy for one bucket and one key prefix (`YOUR_PREFIX` = the account
`prefix`, default `9drive`):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "9DriveList",
      "Effect": "Allow",
      "Action": ["s3:ListBucket", "s3:GetBucketLocation"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET",
      "Condition": { "StringLike": { "s3:prefix": ["YOUR_PREFIX/*"] } }
    },
    {
      "Sid": "9DriveObjects",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject",
        "s3:AbortMultipartUpload",
        "s3:ListMultipartUploadParts"
      ],
      "Resource": "arn:aws:s3:::YOUR_BUCKET/YOUR_PREFIX/*"
    }
  ]
}
```

Notes: `HeadBucket`/`HeadObject` are authorised by `s3:ListBucket`/`s3:GetObject`;
`CopyObject` (rename/move/copy) needs read on the source **and** write on the target, both
covered above; batch `DeleteObjects` maps to `s3:DeleteObject`.

## Key layout and tenant isolation (contract §11)

- Root per user: `{prefix}/{userId}` (`namespaceRoot`, prefix default `9drive`,
  normalised to bare `a/b` segments — never `.`/`..`).
- File: `{prefix}/{userId}/{fileId}/{fileName}`; folder marker:
  `{prefix}/{userId}/{folderId}/{folderName}/` — a zero-byte object with
  `Content-Type: application/x-directory`.
- `fileId`/`folderId` are random `f`/`d` + 24 hex chars (`newKeySegment`).
- Upload/createFolder names are sanitised: separators flattened to `-`, control
  characters stripped, 180 char cap, `.`/`..`/blank → `ERR_INVALID_INPUT`.
- Every remoteId that arrives from a caller goes through `assertOwnKey` **before** any
  request: anything outside `prefix/userId` → `ERR_NOT_FOUND` (404-shaped, never reveals
  other tenants). Listings only ever scan the caller's own prefix.
- `parseChild` only yields *direct* children of a directory (exactly two relative
  segments), so nested keys never leak into a page.

## Settings resolution

`resolveSettings(ctx)` builds one `S3Settings` from credentials + `account.config`:

| Field | Precedence | Default |
|---|---|---|
| `bucket` | `config.bucket` → `credentials.bucket` | required, else `ERR_INVALID_INPUT` |
| `endpoint` | `config.endpoint` → `credentials.endpoint` → preset → AWS default | `null` (trailing `/` stripped) |
| `region` | `config.region` → `credentials.region` → preset | `us-east-1` |
| `forcePathStyle` | `config` → `credentials` → preset | `true` when an endpoint is set, else `false` |
| `prefix` | `config.prefix` → `credentials.prefix` | `9drive` |
| `quotaBytes` | `config.quotaBytes` (digit string/bigint) | `null` (unlimited) |
| `multipartThresholdBytes` | `config` | 8 MiB (clamped 1 … 5 GiB) |
| `multipartPartBytes` | `config` | 5 MiB (clamped 1024 … 5 GiB) |

Production contexts arrive with `config.endpoint`/`config.forcePathStyle`/`config.region`
already resolved from `S3StorageConfig` + catalog preset by `providers/context.ts`
(DB value → metadata → preset); the adapter applies the same precedence again so direct
API contexts behave identically. Bucket names containing `/ \ whitespace` or equal to
`.`/`..` are rejected; non-`access_key` credentials are rejected before any request.

## Presets (catalog `s3Preset`)

`resolveS3Target({ preset, endpoint, region, forcePathStyle })` merges **explicit user
value > named preset > built-in default**. Unknown preset id → `ERR_INVALID_INPUT`.

| Preset id | Endpoint | Region | Path style |
|---|---|---|---|
| `backblaze_b2` | `https://s3.us-west-001.backblazeb2.com` | `us-west-001` | no |
| `cloudflare_r2` | `https://<account_id>.r2.cloudflarestorage.com` | `auto` | no |
| `idrive_e2` | `https://s3.us-east-1.idrivee2-aws.com` | `us-east-1` | no |
| `internxt` | `https://s3.internxt.com` | `us-east-1` | no |
| `minio` | `http://127.0.0.1:9000` | `us-east-1` | **yes** |
| `wasabi` | `https://s3.wasabisys.com` | `us-east-1` | no |

- **R2**: the catalog value is a template — `https://<account_id>.…` fails URL parsing,
  so the connect route/SSRF gate rejects it until the user supplies their real
  `https://<account_id>.r2.cloudflarestorage.com` endpoint.
- **MinIO preset is localhost**: it only works when the deployment allowlists the host
  (`SSRF_ALLOWLIST=127.0.0.1`) and permits plain HTTP (`ALLOW_INSECURE_ENDPOINTS=true`);
  otherwise `assertUrlAllowed` rejects it with `ERR_SSRF_BLOCKED` (see §SSRF). This is
  intentional for same-host MinIO, and is the reason the fake-server tests set those two
  env flags.
- VIA_S3 catalog ids are presets only — the connected account always reports
  `provider: 's3'`; there is no per-preset adapter.

## Capabilities

The catalog declares 16 capabilities (and `s3Provider.getCapabilities()` mirrors them —
asserted in `s3.presets.test.ts`): `authenticate`, `getAccountInfo`, `getQuota`,
`upload`, `uploadResumable`, `download`, `downloadRange`, `list`, `getMetadata`,
`createFolder`, `rename`, `move`, `copy`, `delete`, `createShare`, `healthCheck`.

- Not declared: **`search`** and **`revokeShare`**. `revokeShare` throws
  `ERR_CAPABILITY_UNSUPPORTED`; shares are revoked only by expiry (there is no S3 API to
  invalidate a presigned URL early).
- Every method gates first with `` `provider 's3' does not declare capability '<name>'` ``
  (before any network call); `createS3Provider({ capabilities })` overrides the set in
  tests.

## Upload protocol

Input validation (before any request): `fileName` required, `stream` must be readable,
`sizeBytes` must be a non-negative `bigint` no larger than
`MAX_OBJECT_BYTES = Number.MAX_SAFE_INTEGER`; a `resumeToken` requires the
`uploadResumable` capability.

- **Zero bytes**: `PutObject` with an empty body; the stream must deliver nothing (else
  `ERR_INVALID_INPUT`); resume tokens are rejected for empty uploads.
- **Single part** (`sizeBytes <= multipartThresholdBytes`, default 8 MiB): streaming
  `PutObject` with a declared `Content-Length`. The body is `guardedBody()` — pull-based,
  so a size mismatch is detected *in flight*: over-delivery and under-delivery both abort
  the request and raise `ERR_INVALID_INPUT` (a short body with fixed Content-Length would
  otherwise hang S3 forever); source failures surface as
  `ERR_UPSTREAM_UNAVAILABLE`/`ProviderError`, and no `error` event is emitted for the SDK
  to leak.
- **Multipart** (larger, or when resuming): `CreateMultipartUpload` → `UploadPart` per
  `partSize` → `CompleteMultipartUpload`. `partSize = max(multipartPartBytes,
  ceil(size/10000))`, so the part count can never exceed `MAX_MULTIPART_PARTS` (10 000,
  else `ERR_INVALID_INPUT`). Parts are read into exact-size buffers from the stream
  (`StreamCursor.read`); a stream that ends early → `ERR_INVALID_INPUT`, extra bytes →
  `ERR_INVALID_INPUT`, iterator failure → `ERR_UPSTREAM_UNAVAILABLE`.
- **Resume tokens**: only *retryable* failures (`ERR_RATE_LIMITED`,
  `ERR_UPSTREAM_UNAVAILABLE`, `ERR_TIMEOUT`) carry `detail.resumeToken` — a JSON
  `{v: 1, key, uploadId, partSize, size}` (bigint stringified). Non-retryable failures
  never attach one. On resume the adapter validates the token (JSON/shape/version,
  same namespace via `assertOwnKey`, same folder, same size and part size — mismatch →
  `ERR_INVALID_INPUT`), calls `ListParts`, and skips parts whose ETags are already
  present; the caller re-sends the stream from the start, but completed parts are not
  re-uploaded.

## Download

- Folders → `ERR_INVALID_INPUT`; foreign keys → `ERR_NOT_FOUND`.
- Without a range: `GetObject`, `sizeBytes` from `Content-Length`, `mimeType` from
  `Content-Type` (falls back to the extension table).
- With a range (capability `downloadRange`, checked before the request): `Range:
  bytes=start-end`; the response `Content-Range` is parsed back into
  `range { start, end, total }`. S3 clamps `end` to the object size (the adapter reports
  the served window); a start beyond the object → 416 → `ERR_INVALID_INPUT`.

## Listing, cursors and metadata

- `list` scans the directory prefix with `ListObjectsV2`, keeps direct children only,
  sorts by name (folder markers sort with their name — no "folders first" rule) and pages
  with an **offset cursor** (base64 of the numeric offset; opaque to callers, malformed →
  `ERR_INVALID_INPUT`).
- `limit`: default 100, max 1000 (`pageLimit`), non-integer/`< 1` → `ERR_INVALID_INPUT`.
- `parentId`: `null` → account root; must be inside the namespace and end with `/`
  (a file key or foreign key → `ERR_NOT_FOUND`).
- `RemoteFileMeta`: `modifiedAt`/`checksum` come from `LastModified`/`ETag` (quotes
  stripped) for list, and from `HeadObject` for single-object reads; folders report
  `mimeType: inode/directory`, `sizeBytes: 0n`; `createdAt` and `webUrl` are always
  `null` (S3 has neither).
- `getMetadata` = `assertOwnKey` + `HeadObject` (missing → `ERR_NOT_FOUND`).

## Folder operations, rename/move/copy/delete

- `createFolder` scans the parent first and reuses an existing marker with the same
  name (idempotent, no second `PutObject`), then writes the zero-byte marker.
- **rename**: `HeadObject` first; same name short-circuits. Files: `CopyObject` next to
  the original + `DeleteObject` (the `fileId` segment is kept). Folders: subtree
  `CopyObject` loop + `DeleteObjects` of the old prefix.
- **move**: same-directory moves short-circuit (no request beyond the HEAD). Files copy
  into the target directory (same `fileId`) + delete the source; folders rebase the whole
  subtree. Moving/copying a folder **into itself** → `ERR_INVALID_INPUT`.
- **copy**: always allocates a fresh `fileId`/`folderId` segment; folders copy marker +
  descendants, source untouched.
- **delete**: `HeadObject` first (missing → `ERR_NOT_FOUND`, foreign keys are rejected
  before any request). Files: `DeleteObject`; folders: `DeleteObjects` in batches
  (`Quiet: true`) over the whole prefix. Per-key `<Error>` entries in a 200 response are
  mapped (e.g. `AccessDenied` → `ERR_AUTH_REVOKED`).
- **There is no trash**: `DeleteInput.permanent` is ignored — S3 deletes are final.

## Sharing (presigned GET)

- Only `visibility: 'public_read'` (anything else → `ERR_INVALID_INPUT`); folders cannot
  be shared; the object must exist and belong to the caller.
- URL: SigV4 presigned `GET` built by `presign.ts` with the standalone
  `@smithy/signature-v4` signer (`uriEscapePath: false`, `applyChecksum: false`,
  signed header `host`). Expiry: `resolveShareExpiresIn` — default 3600 s, `ceil` of the
  requested `expiresAt` delta, clamped to 7 days (`MAX_PRESIGN_SECONDS = 604800`, SigV4
  limit), past/invalid timestamps → `ERR_INVALID_INPUT`.
- Addressing mirrors the client (`objectTarget`): custom endpoint + `forcePathStyle` →
  `host:port/bucket/key`; virtual-host style → `bucket.host/key` (key segments
  percent-encoded exactly once); AWS default → `bucket.s3.{region}.amazonaws.com`.
- The endpoint passes `assertUrlAllowed` again before signing, so a share can never be
  minted for a blocked host. URLs contain only the access key id in the credential scope
  — never the secret (asserted in tests via an independent SigV4 verifier).

## Quota

`getQuota` aggregates `ListObjectsV2` under `prefix/userId/` across up to
`MAX_QUOTA_PAGES` (10 000) pages: `usedBytes` (bigint sum), `raw.objectCount/pages/
truncated`, `raw.approximate: true`, `raw.source: 'ListObjectsV2'`. `totalBytes` comes
from `config.quotaBytes`; `availableBytes = max(total - used, 0)`; no configured quota →
`null`. All arithmetic is `bigint`; transport through `jsonSafe`/`serializeBigInt`
(`backend/src/utils/serialize.ts`) turns bigints into strings — plain `JSON.stringify`
of a `QuotaInfo` throws (asserted in `s3.quota.test.ts`).

## Error mapping (contract §5)

`mapS3Error(error, operation)` passes `ProviderError`s (and `ProviderError` causes)
through untouched; otherwise it inspects `name`/`Code`/`code` + `$metadata
.httpStatusCode`/`statusCode`. Messages are `"<operation> …"` only — no URLs, no
credential material; raw detail stays on `detail` (`{ codes, status }`).

| Signal | Code | Retryable |
|---|---|---|
| `TimeoutError`/`RequestTimeout`/`ETIMEDOUT`/abort | `ERR_TIMEOUT` | yes |
| `InvalidRange` / 416 | `ERR_INVALID_INPUT` | no |
| `NoSuchKey`/`NoSuchBucket`/`NoSuchUpload`/`NotFound`/404 | `ERR_NOT_FOUND` | no |
| `QuotaExceeded`/507 | `ERR_QUOTA_EXCEEDED` | no |
| `SlowDown`/`Throttling*`/`TooManyRequests`/429 | `ERR_RATE_LIMITED` | yes |
| 401 | `ERR_AUTH_EXPIRED` | no |
| 403 / `AccessDenied`/`SignatureDoesNotMatch`/`InvalidAccessKeyId`/… | `ERR_AUTH_REVOKED` | no |
| any 5xx | `ERR_UPSTREAM_UNAVAILABLE` | yes |
| `ECONNREFUSED`/`ENOTFOUND`/`ECONNRESET`/… , `TypeError('fetch failed')` | `ERR_UPSTREAM_UNAVAILABLE` | yes |
| anything else with a status | `fromHttpStatus(status)` | — |
| anything else | `ERR_INTERNAL` | no |

`healthCheck` never throws: it maps the same errors through `mapErrorToHealthState`
(`health.ts`) — `healthy` on success, `ERR_NOT_FOUND` → `degraded`, `ERR_AUTH_*` →
`unauthorized`, `ERR_UPSTREAM_UNAVAILABLE`/`ERR_TIMEOUT` → `unreachable`, `ERR_SSRF_BLOCKED`
→ `degraded`.

## SSRF and endpoint security (security-contract §6/§7)

Two layers, both from `backend/src/utils/ssrf.ts`:

1. **`buildClient()` → `assertUrlAllowed(endpoint)`** on every session open: HTTPS only
   (unless `ALLOW_INSECURE_ENDPOINTS=true`), no credentials in the URL, no fragments,
   ports limited to 80/443/9000/9001, blocked hostnames (`localhost`, `metadata`,
   `metadata.google.internal`, `instance-data`) and suffixes (`.local`, `.internal`,
   `.localhost`, `.localdomain`) rejected — `ERR_SSRF_BLOCKED`.
2. **`sendCommand()` → `assertFetchAllowed()` per request** (after DNS resolution via
   `assertResolvedAddressesAllowed`): loopback/link-local/metadata/private ranges are
   rejected even when the hostname itself is not on a blocklist.

`SSRF_ALLOWLIST=<host>` skips both checks for exactly those hostnames (any port) — the
mechanism the fake-server tests use for `127.0.0.1`. Credentials are decrypted per call
into the context, never logged (`ctx.logger` receives operation metadata only), and the
caller's `ctx.signal` is combined with per-command signals (`AbortSignal.any`) so an
aborted upload stops mid-flight.

## Account probe and health

- `authenticate` / `getAccountInfo`: `HeadBucket`; success → `{ ok: true }` and
  `{ providerAccountId, email: null, displayName, avatarUrl: null }`; missing bucket →
  `ERR_NOT_FOUND`, denied → `ERR_AUTH_REVOKED`.
- `healthCheck`: same probe wrapped by `mapErrorToHealthState` (table above) with
  `latencyMs` and `checkedAt`.

## Rate limits and retries

- The AWS SDK retries retryable failures with exponential backoff
  (`maxAttempts: 3`, single `sendCommand` call). The adapter itself does **not** retry —
  429/`SlowDown` surfaces as `ERR_RATE_LIMITED` after the SDK budget and pacing belongs
  to the caller/job backoff (`job-contract.md`).
- `requestChecksumCalculation: 'WHEN_REQUIRED'`: plain PUT/GET bodies stay compatible
  with every S3-compatible endpoint (aws-chunked trailer checksums are not universal).
- Multipart quotas: 10 000 parts max; part size auto-raised for huge objects; a completed
  `CompleteMultipartUpload` counts as one `upload` operation.

## Limitations (contract scope)

- **No `search`** and **no `revokeShare`** (both undeclared); S3 has no server-side
  name query within the contract's object model, and presigned URLs can only expire.
- **No trash/restore** — `delete` is always permanent.
- **Folders are synthetic**: markers can be deleted out from under children (the adapter
  never validates marker presence on list), and folder copy/rename/delete is a sequence
  of object operations, not an atomic server transaction.
- **Declared size is mandatory** (`sizeBytes`), so unknown-length streams must be
  measured by the caller; resume tokens bind size + part size.
- **Quota is approximate and read-heavy**: it lists the whole namespace (up to 10 000
  pages of 1000 keys) on every `getQuota`; `raw.approximate: true` documents that.
- **`cloudflare_r2` preset endpoint is a placeholder** (see Presets) — always override.
- Listing has no server-side sort/filter: ordering is by name only, case-sensitive.

## Test harness

`backend/src/__tests__/providers/s3/helpers.ts` provides a deterministic in-process fake
S3 (`startFakeS3`: path-style routing, virtual-host tolerant, `ListObjectsV2` paging via
`pageKeys`, multipart lifecycle, scripted failures `failNext({operation,status,code,
bodyXml,times})`, request recording), `makeS3Context`, `expectProviderCode` and an
independent SigV4 verifier (`verifyPresignedUrl`). `withFakeS3()` sets
`ALLOW_INSECURE_ENDPOINTS=true` + `SSRF_ALLOWLIST=127.0.0.1`, points the context at the
fake and restores the environment afterwards — no production transport seam is needed
because the endpoint is ordinary account configuration (unlike the Google Drive adapter).

Coverage (8 files, 80 tests): `s3.upload.test.ts` (single/zero/multipart, guards,
resume), `s3.keys.test.ts` (layout/sanitisation/isolation units), `s3.presets.test.ts`
(preset merge, settings, capability gating, SSRF rejections — runs with a clean env),
`s3.objects.test.ts` (list/paging/meta/folder/rename/move/copy/delete/download/ranges),
`s3.quota.test.ts`, `s3.errors.test.ts` (unit + live §5 mapping, retry budgets,
connection refusal), `s3.health.test.ts` (account probe + health states),
`s3.share.test.ts` (presign verification, expiry clamping, addressing styles).

## Registration and catalog parity

`registerS3Provider()` registers the `s3Provider` singleton in `provider-registry`
(id `s3`, `displayName: 'S3-compatible'`, `authMode: 'access_key'`), which
`providers/index.ts` calls; `createS3Provider()` exists for tests. Declared capabilities
are asserted equal to the catalog's `S3_CAPABILITIES` set.

## Requests to the coordinator

- `presign.ts` imports `@smithy/signature-v4`, which is only available as a transitive
  dependency of `@aws-sdk/client-s3` (it is not listed in `backend/package.json`).
  Declaring it explicitly would protect the adapter from an upstream hoisting change —
  this agent cannot edit `package.json`.
- The `cloudflare_r2` catalog preset should eventually ship as a documented
  "enter your account id" field rather than a literal `<account_id>` URL template,
  since the template always fails the SSRF gate on first connect.
